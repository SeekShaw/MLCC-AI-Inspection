# EcompVision Inspector 软件功能规格与测试用例设计

> **本文件为唯一权威文档**，取代并合并了原 `功能规格说明书.md` 与 `测试用例设计.md`（两份已删除）；规格与用例放在同一文件、同章节、同编号，改功能时一处更新即可。
> 适用版本 **V3.6.6.0**（唯一来源 `src/app_meta.py`）
> 需求基线：`smoke_issues.py` 的 **68 个需求分节**（开发至今所有最终确认后的功能效果）+ `src/` 全量源码逐项核对
> 自动化现状：`python smoke_issues.py` 运行时 **995 条 PASS/FAIL 断言**；验收标准 `ALL_PASS`、0 FAIL、无 Traceback（Windows PowerShell 需 `PYTHONIOENCODING=utf-8`）

## 0. 文档说明与维护规则

### 0.1 编号与颗粒度规则

| 项 | 规则 |
|---|---|
| 规格编号 | `S-<章节>.<序号>`，一条编号对应**一个**控件/参数/按钮，不合并同类项 |
| 用例编号 | `T-<章节>.<序号>`，与同号 `S` 一一对应；规格改了就改同号用例，功能回退标「已废弃」并保留历史行 |
| 用例颗粒度 | **一条用例只验证一个控件的一个效果**。默认值校验、修改生效、边界钳制、权限拦截、置灰条件、弹窗文案分别独立成条；需要多步 precondition 的用 `T-x.y-a/b/c` 后缀细分 |
| 模块代码 | `1` 全局、`2` 主窗口、`3` 生产运行、`4` 相机调试、`5` 设置窗口、`6` 用户与权限、`7` 产品与其它窗口、`8` 基线映射 |
| 优先级 | P0 核心/安全/权限、P1 主流程、P2 边界与展示、P3 占位与兼容 |
| 前置缩写 | `超管`／`普通`＝账号类别；`停止态`／`运行态`＝设备是否启动；`有/无权限`＝该键在类别矩阵的值；`会话`＝`MainWindow._adv_settings` 内存字典 |
| 基线列 | `S<nn>`＝`smoke_issues.py` 第 nn 个需求分节；`V3.6.x`＝对应版本新确认效果 |

### 0.2 强制维护流程（每次功能新增/修改/删除/缺陷修复）

1. 在本文件对应模块的 **`S-x.y` 规格行**补充或修正「默认值 / 范围 / 键 / 效果 / 权限」。
2. 同步更新**同号 `T-x.y` 用例**；新增功能点按序追加新编号（编号只增不改、不复用）。
3. 在 `smoke_issues.py` 追加 `check(cond, msg)` 断言，分节注释写明日期与需求。
4. `python -m py_compile ...` → `python smoke_issues.py`，确认 `ALL_PASS`、0 FAIL、无 Traceback。
5. 在第 9 章「变更记录」追加一行（日期 / 版本 / 变更 / 新增或修订编号 / 回归条数变化）；涉及 UI/状态机改动再 `python build_b.py` 打包并提交。

> 单文件好处：规格与用例同号相邻，避免两份文档版本号、编号、变更记录漂移；`git diff` 一次即可审阅功能与验收的同步性。

### 0.3 生效时序术语（规格表「落盘」列）

| 术语 | 含义 |
|---|---|
| `实时(内存)` | 改 `dev_cfg` 并刷新模拟数据，但**不写盘**，重启丢失 |
| `实时+落盘` | 控件信号直接改配置并 `save_*()`，无需点保存 |
| `需应用/保存` | 先入 `_work` 工作副本，点「应用」或「保存」才提交 |
| `仅保存` | 只有「保存」按钮写入，「应用」也不写 |
| `会话` | 写 `MainWindow._adv_settings`，重启不保留，且多数键当前无消费点 |
| `不落盘` | 纯 UI／纯日志／纯弹窗 |
