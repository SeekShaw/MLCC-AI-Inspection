# EcompVision Inspector 测试用例设计

> 适用版本：V3.6.6.0
> 需求基线：`smoke_issues.py` 的 **68 个需求分节**（开发至今所有最终确认后的功能效果）+ `docs/功能规格说明书.md`
> 自动化现状：`python smoke_issues.py` 运行时输出 **995 条 PASS/FAIL 断言**（静态 `check` 调用点 ≥809，循环/分支会放大执行条数），验收标准 `ALL_PASS`、0 FAIL、无 Traceback
> 配套文档：`docs/功能规格说明书.md`

---

## 0. 维护规则（强制）

**每一次功能新增、修改、删除或缺陷修复，都必须同步完成以下 5 步，缺一不可：**

1. 在 `docs/功能规格说明书.md` 对应章节补充/修正界面、按钮、参数及「点击/设置后效果」描述。
2. 在本文档新增或修订 `TC-XX-NNN` 用例（含前置条件、步骤、预期结果、基线分节）。
3. 在 `smoke_issues.py` 追加对应的 `check(cond, msg)` 断言，分节注释写明日期与需求。
4. 依次执行 `python -m py_compile ...` → `python smoke_issues.py`，确认 `ALL_PASS`、0 FAIL、无 Traceback（Windows PowerShell 需 `PYTHONIOENCODING=utf-8`）。
5. 在两个文档末尾「变更记录」各追加一行，注明日期、版本、变更内容、对应用例编号；涉及 UI/状态机改动时重新 `python build_b.py` 打包并提交。

用例编号只增不改、不复用；功能回退时用例标记「已废弃」并保留历史行。

## 1. 用例约定

| 项 | 约定 |
|---|---|
| 编号 | `TC-<模块>-<三位序号>`；模块见第 0 章规格说明书 |
| 优先级 | P0 核心/安全/权限、P1 主流程、P2 边界与展示、P3 占位与兼容 |
| 前置条件缩写 | `超管`＝超级管理员登录；`普通`＝非超管类别登录；`停止态`＝未点设备启动；`运行态`＝设备启动后；`有/无权限`＝对应权限键在类别矩阵中的值 |
| 基线列 | `S<nn>`＝`smoke_issues.py` 第 nn 个需求分节；`V3.6.x`＝对应版本新确认效果；`规格 §x.y`＝功能规格说明书章节 |
| 执行方式 | 优先自动化（`smoke_issues.py` offscreen），交互/视觉类用手工；自动化断言文案与用例预期结果一一对应 |
